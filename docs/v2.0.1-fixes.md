# LinzinDeskClock 2.0.1 corrections

## Changes requested

1. Fix divider release snapping and add 30% and 70% anchors.
2. Match the supplied media reference: full cover and a lower frosted player surface.
3. Offer a notification-access settings button when media access is missing.
4. After one-time setup, show the clock when locking from another app with the phone landscape on a stand.

## Implementation

- Three release bands: 25–35% → 30%, 45–55% → 50%, 65–75% → 70%. Dragging remains continuous. The release decision uses the same rounded pixels as the displayed divider, including rounded band edges. This fixes reproduced Float boundary misses. Tests exercise the production DeskClockScreen, hoisted pagers, callbacks and saved ratio. A general failure of every centre snap was not reproduced; no broader root cause is claimed.
- The media page has a fitted cover with mirrored blurred margins, centred white title/artist, elapsed/seek/duration, a larger circular play/pause button and adjacent previous/next controls. The lower surface uses a separately blurred artwork layer, leaving the original cover clear. Narrow or short panels adapt without removing touch targets.
- Missing media access displays 前往通知存取權, opens the exact listener settings with an OEM fallback, and rechecks on resume. Locked sessions display an unlock hint instead of navigating into settings.
- Automatic opening is explicitly enabled separately from monitoring. The consent dialog explains Android's Display over other apps special access before opening its system settings. The app creates no overlay window; it uses the documented user-granted SYSTEM_ALERT_WINDOW background Activity exception to start its normal, unexported clock Activity once.
- The monitor survives closing/removing the main task. An opted-in service can resume on boot or Android service restart. Boot never scans or launches the clock. Force-stop still requires reopening the app. No package-replaced receiver is installed, so APK installation itself does not start the app.
- Lock-cycle identity, deadline, charging, posture, consent, live permission and keyguard are rechecked. Display off/doze transitions supplement protected system broadcasts. USER_PRESENT is accepted from privileged System UI; only protected actions are registered and actual device state is verified.
- The clock retains its one-shot screen-on request through initial orientation/keyguard transitions until window focus. A temporary onStop no longer counts as manual exit. A ViewModel preserves an authorised session across configuration recreation; process death never revives an expired offer. Exit still suppresses the current lock cycle.
- Fresh charging defaults to No charging requirement; previously stored choices are preserved. Settings now report scan/no-match/notification/requested/shown/blocked outcomes rather than equating a launch request with a displayed window.

## Enabling the revised behaviour

Open 設定自動桌面時鐘 on the welcome page, or the clock settings. Enable 從任何 App 鎖屏後自動開啟, read the explanation, and allow 顯示在其他應用程式上層 on the system page. Confirm the monitor is running. For an ordinary unpowered stand, select 不要求充電. Then leave the app, use another app, place the phone landscape at 30°–75° and lock it. The original five-second scan and 1.5-second stability requirement still apply.

Some OEMs additionally require permission for background activity/auto-start. A manual permission grant is required; this update does not grant special access on the user's phone. Without the permission or if a manufacturer blocks the request, the app retains a ready notification and reports the missing/blocked state. No root, Shizuku, accessibility or keyguard dismissal was added.

## Verification

Local build and test outputs are under .local/revision-*.log. The repeatable scripts/verify-background-clock.py refuses physical devices, verifies emulator identity, backgrounds the main activity, locks, requires a focused awake ClockSessionActivity, checks sustained display/configuration recreation, exits, then verifies another lock works without reopening the main activity. It is also run in hosted CI.

The isolated emulator has already demonstrated the background launch, configuration recreation, exit suppression, and unlock/relock without reopening MainActivity. Final test counts, screenshots and the updated install receipt are recorded in the completion report after the remaining suite finishes. Personal-phone testing remains prohibited; install only, never launch.
