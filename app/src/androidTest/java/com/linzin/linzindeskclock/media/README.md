# Media instrumentation handoff

The suite contains seven repository tests and three hardware rendering tests. It changes no production sources, manifests, dependencies or existing tests.

## Execution boundary

Only the parent may build/install/run this suite on the verified dedicated emulator. Do not run it on the personal phone. Do not use connectedDebugAndroidTest, an unqualified adb command, or a device-selection default. Nothing in these test sources installs an APK or launches MainActivity; the rendering tests use the existing debug test-manifest ComponentActivity host.

The outermost JUnit rule requires ALL of:

- Build.HARDWARE is ranchu, goldfish or cutf_*.
- Build.FINGERPRINT identifies generic, sdk_gphone, sdk_phone or vsoc_*.
- Instrumentation argument linzinDedicatedMediaEmulator is exactly true.
- API level is at least 31.
- The target process runs as system user 0 (not a work or secondary profile).

A failed precondition is a JUnit assumption skip, not a test pass. These checks precede the Compose ActivityScenario rule and every notification-access shell command. An incorrectly selected instrumentation target would still start Android's instrumentation/application process before JUnit can guard it, so the parent MUST verify the emulator serial before any install or run. The guard is additional protection, not authorisation to target a phone.

## Permission fixture and cleanup

Only cmd notification allow_listener/disallow_listener for com.linzin.linzindeskclock/.media.ClockNotificationListenerService and explicit user 0 are used. The lease records this exact component's prior grant and the other enabled listeners. Nested use blocks stop the repository, release fixture sessions, and restore the prior grant in finally, including failed tests and failed grants. Other listeners are checked for changes but never written. A restoration failure fails the test. No shell identity or MEDIA_CONTENT_CONTROL permission is adopted for repository calls, so revocation exercises the real app permission path.

All repository operations and MediaSession mutations run on the main looper through an 8-second bounded FutureTask. Repository/callback waits observe StateFlow with an 8-second deadline. Permission polling checks a condition every 25 ms within the same deadline; shell output has a 5-second deadline. Negative callback/state assertions deliberately observe 350 ms and do not prove indefinite silence. Pixel tests use explicit Compose animation-clock steps, hardware frame-commit fences and PixelCopy completion latches, not long settling sleeps.

If instrumentation is forcibly killed or the emulator crashes, Kotlin finally cannot run. The parent must inspect and restore the recorded prior listener setting on that dedicated emulator before reusing it. Do not attempt restoration on another device.

## Rendering evidence

The hardware tests require a visible, focused hardware-accelerated host with enough space for a 336x336 dp fixture. PixelCopy captures at most 2048x2048 pixels. RGB comparisons allow 24 levels of GPU rounding; mirror direction and blur contrast are checked separately. Expected fit coordinates are hand-derived, not generated by the production geometry helper.

Only six fixed-name PNGs are written, overwriting previous files, under the target app's external cache directory media-instrumentation:

- portrait-fit-mirror-blur.png
- landscape-fit-mirror-blur.png
- crossfade-before.png
- crossfade-middle.png
- crossfade-after.png
- missing-artwork-cleared.png

Each capture emits its actual device path as instrumentation status media_artwork_capture. On the primary emulator this is normally /sdcard/Android/data/com.linzin.linzindeskclock/cache/media-instrumentation/. The parent can pull that directory to D: using the same verified emulator serial. PNGs contain only generated test artwork and a magenta clipping guard. There are no real notifications, personal covers or proprietary music applications in the fixtures.

## What the tests cover

Repository tests exercise platform MediaSessionManager discovery, actual target-process MediaSession callbacks for play/pause/next/previous/seek/media-button toggle, unsupported/stale/blocked command rejection, metadata and missing-art updates, bitmap downsampling, playing-session selection, release/deactivation/reselection, stop/restart and pending-result cleanup. A revocation test waits for state to clear before calling dispatch, then re-grants access and verifies a fresh session identity can dispatch again.

Pixel tests exercise the production AlbumArtBackground composable on a hardware Canvas: whole-image fit in both aspect directions, sharp original colour edges, mirrored (not clamped or normally repeated) surrounding rectangles, blurred extension edges, no drawing beyond the panel, intermediate and final crossfade pixels, and clearing old art when artwork becomes null.

This is not a full Android build or runtime result until the parent runs it. It does not prove OEM-specific listener behaviour, long-duration leaks, arbitrary remote music apps, actual keyguard unlock/lock transitions, Dream-host lifecycle integration, or the MediaWidget overlay's visual accessibility. It does not play audio, dismiss Keyguard, open settings or operate the personal phone.
